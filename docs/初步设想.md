# 一、先把 Vibero 拆成 7 个一级模块

这是最适合逆向理解它的方式。

## 1. 文献接入层：Zotero 集成

官网原文已经很明确：**“基于 Zotero 的全新 AI 论文阅读器”“完全共享文献库、插件、生态与社区”**。

这说明它大概率不是自己重造文献管理，而是走这条路线：

- 直接读取 Zotero 本地数据库 / 附件目录
- 或通过 Zotero 插件 / 本地 API / WebDAV 同步桥接
- 复用 Zotero 的：
  - 文献条目
  - 附件 PDF
  - tags
  - collections
  - notes
  - metadata

### 你逆向时要得出的关键判断

Vibero 的“护城河”未必在文献管理，而在于：

- **AI 解析流程**
- **交互式阅读 UI**
- **上下文编排**
- **论文+代码联合问答**
- **Credits 计费体系**

### 自主实现建议

不要第一阶段自己做 bibliographic manager，直接选一种：

- **方案 A：Zotero 插件**
- **方案 B：桌面端读取 Zotero 数据目录**
- **方案 C：通过 Better BibTeX / Zotero API 做桥接**

如果你想最快跑通 MVP，优先级是：

**先接 Zotero 附件与 metadata，再做 AI 画布。**

## 2. 文档解析层：PDF → 结构化语义对象

官网说“将论文变成交互式 AI 画布”，这句话背后的真实含义是：

> 必须先把 PDF 从“页面图像/文本块”转成“可引用、可定位、可问答、可拖拽”的结构化对象。

所以它内部一定有一个**VIBE 解析流水线**。官网 FAQ 也单独提到：

- **VIBE 解析每页消费 1 credit**
- AI 对话每次消耗 8 credits

这说明“解析”和“对话”是两个独立计费动作，也说明解析是一个相对重的后端任务，而不是前端临时抽文本。

### 这个解析层大概率包含什么

至少包含：

#### (1) PDF 基础解析

- 页码
- 文本块
- 字体大小 / 标题层级
- 段落切分
- 参考文献区识别
- 图表区域检测
- caption 提取

#### (2) 版面结构重建

把 PDF 变成：

- title
- authors
- abstract
- introduction
- methods
- results
- discussion
- figures
- tables
- equations
- references

#### (3) 语义索引

- chunk embedding
- section embedding
- figure/table semantic summary
- key claims
- contributions
- limitations
- methods summary

#### (4) 可交互锚点系统

这是它画布可用的关键：

- 每个段落有唯一 ID
- 每个图、表、公式有唯一 ID
- 每个对象都能回链到原 PDF 页码与 bounding box
- 支持点击、框选、拖拽触发上下文查询

### 你自主实现时的落地做法

建议拆成三层对象模型：

```text
Paper
 ├── Metadata
 ├── Sections[]
 │    ├── Paragraphs[]
 │    ├── Figures[]
 │    ├── Tables[]
 │    └── Equations[]
 ├── Chunks[]
 ├── Citations[]
 └── PageAnchors[]
```

每个对象都要带：

- `id`
- `paper_id`
- `page`
- `bbox`
- `text/raw_content`
- `normalized_content`
- `embedding`
- `source_type`

### 你第一版不要追求什么

不要一开始就做：

- 超强 OCR
- 完美公式理解
- 所有 PDF 全兼容

先支持：

- 学术论文双栏 PDF
- 文字层可提取
- 图表 caption 可定位
- section 基本正确

这就够做出第一版“可交互 AI 阅读器”。

## 3. 交互画布层：静态阅读器 → 非线性工作区

官网最重要的一个词就是：**非线性阅读**。

这意味着它不是传统的：

- 左边 PDF
- 右边聊天框

而是更像：

- 一个无限画布 / 白板式工作区
- 用户可以把论文中的片段“拉出来”
- AI 回答也能“贴回去”
- 形成自己的研究笔记网络

### 这层的真实产品逻辑

所谓“画布”至少要支持四种节点：

1. **源节点**
   - 论文段落
   - 图表
   - 表格
   - 公式
   - 代码片段

2. **AI 节点**
   - 对某个问题的回答
   - 某段内容的解释
   - 方法总结
   - 对比分析

3. **用户节点**
   - 手写/文本笔记
   - 研究假设
   - TODO
   - 批注

4. **关系边**
   - 引用关系
   - 推导关系
   - 对比关系
   - “由此得出”关系

### 官网那句“画布 ↔ AI 对话”怎么实现

它至少需要两个方向：

#### 方向 A：画布 → 对话

用户点击或框选一个对象，发起：

- “解释这个公式”
- “这个图说明了什么”
- “比较 section 2 和 section 4”
- “这段和代码实现如何对应”

此时系统构造 prompt：

- 当前选中对象内容
- 邻近上下文
- 论文全局摘要
- 用户当前对话历史
- 相关代码片段（如果存在）

#### 方向 B：对话 → 画布

AI 回答生成后，不只是显示在聊天窗口，而是可拖到画布成为：

- 一个答案卡片
- 一个摘要卡片
- 一个假设卡片
- 一个对比结论卡片

### 你要怎么自己实现

前端建议直接选：

- **React + Tauri / Electron**
- 画布：`React Flow` / `tldraw` / `Konva`
- PDF 渲染：`pdf.js`
- 拖拽：HTML5 DnD + 自定义节点系统

### 关键数据结构

```ts
type CanvasNode = PaperSnippetNode | FigureNode | TableNode | AiAnswerNode | UserNoteNode | CodeSnippetNode
```

每个 node 要保存：

- 来源对象 ID
- 渲染内容
- 坐标
- 引用链
- 是否可更新
- 是否与当前论文绑定

### 你第一版画布建议

不要一开始做“无限复杂白板”，只做：

- 拖入节点
- 连线
- 简单分组
- 双击编辑
- 节点回跳源 PDF

先把**科研阅读闭环**做通，比做炫酷 UI 更重要。

## 4. AI 对话层：不是普通 RAG，而是“上下文编排式问答”

官网写得很克制，但实际上这块是核心：

- 点击或拖拽即可查询任何内容
- 画布与对话双向联动
- 核心点定位
- 论文与代码协同理解

这说明它的 AI 对话不是单一 prompt，而是一个**上下文路由器**。

### 这层至少分四种问答模式

#### 模式 1：局部解释

针对某个：

- 段落
- 图
- 表
- 公式

例如：

- 这段是什么意思？
- 这张图的横纵轴是什么？
- 这个公式的变量含义是什么？

#### 模式 2：全局综述

例如：

- 这篇文章的创新点是什么？
- 方法流程是什么？
- 与某经典论文相比有什么区别？

#### 模式 3：跨模态联合理解

官网特别强调“论文+代码”，说明它至少支持：

- 论文的方法描述 ↔ GitHub 代码实现 对齐
- 某公式 ↔ 某函数实现 对齐
- 某算法步骤 ↔ 某仓库目录结构 对齐

#### 模式 4：研究辅助

例如：

- 帮我提炼局限性
- 列出可复现实验步骤
- 给我一个 related work 对比框架
- 帮我把这部分做成笔记

### 背后的系统设计

你应该把 AI 层拆成：

#### (1) Query Intent Classifier

识别用户当前问题属于：

- explain
- summarize
- compare
- critique
- reproduce
- code-align
- extract

#### (2) Context Assembler

按意图拼上下文：

- 当前节点
- 邻近段落
- 相关图表
- 全文摘要
- 历史对话
- 代码库索引结果

#### (3) Tool Router

不同问题调用不同子流程：

- 文本 RAG
- 图表解释器
- 代码检索
- 引文抽取器
- 结构摘要器

#### (4) Response Normalizer

把回答变成：

- 对话输出
- 可拖拽卡片
- 结构化笔记

### 你第一版别做得过深

先做这三类：

- explain selected
- summarize section
- align paper with code

只要这三类体验做顺，就已经很像 Vibero 了。

## 5. 代码库问答层：论文与代码协同阅读

官网提到：

- 不限次代码库对话
- GitHub 代码库问答在国内可能要 VPN

这说明这部分大概率是：

- 接 GitHub 仓库
- 拉取代码
- 做代码索引
- 与论文语义链接

### 这层怎么拆

至少分成：

#### (1) Repo ingestion

- 输入 GitHub URL
- clone / shallow clone
- 文件过滤
- 语言识别
- 构建目录树

#### (2) Code parsing

- 按文件分块
- AST 级别提取（优先支持 Python）
- function/class/docstring 提取
- README / config / requirements 识别

#### (3) Code embedding

- chunk embedding
- symbol table
- file summary
- call graph（进阶版）

#### (4) Paper-code alignment

这是核心难点：

- 把论文中 method/algorithm/concept 与代码中实现实体匹配
- 比如：
  - “loss function” ↔ `compute_loss()`
  - “training pipeline” ↔ `train.py`
  - “evaluation metrics” ↔ `eval.py`

### 第一版如何实现

不要一开始做“真正的跨模态深对齐”，先做：

- 论文全文摘要
- README 摘要
- 代码文件摘要
- 基于关键词 + embedding 检索的弱对齐

比如用户问：
“论文中的 method section 在代码里对应哪部分？”
你的系统做：

1. 取 method section summary
2. 搜索 repo summaries / chunks
3. 返回最相近文件与函数
4. 用 LLM 生成解释

先“够用”，再精细化。

## 6. 核心点定位层：把论文关键点主动提出来

官网有一句很关键：**“让 Vibero 引导你直达论文的关键内容”**。

这说明它不是纯被动响应，而是有**主动提炼层**。

### 大概率的功能包括

- 自动提炼：
  - 研究问题
  - 创新点
  - 方法流程
  - 实验设计
  - 结果亮点
  - 局限性

- 自动高亮：
  - title / abstract / contribution claim
  - figure captions
  - result statements
  - limitation statements

### 这层的技术本质

其实是一个“论文结构摘要与显著性排序器”。

### 第一版可直接实现的流程

对论文解析完成后自动生成：

```text
Paper Insight Pack
- 3 sentence summary
- 5 key contributions
- method pipeline
- 3 most important figures
- reproducibility checklist
- likely limitations
```

然后在 UI 中以侧栏/卡片显示。

这样就已经接近官网所说的“核心点定位”。

# 三、真正的难点不在“做出来”，而在“体验做到像产品”

如果你要逆向到“自主实现”，必须知道哪里最难。

## 难点 1：PDF 解析质量

学术 PDF 很脏：

- 双栏
- 多图多表
- 公式
- 脚注
- 参考文献
- 扫描件
- 行内符号混乱

### 解决思路

第一阶段：

- 优先支持可复制文本 PDF
- 借助成熟解析器
- 做 section/figure/caption 基础识别

第二阶段：

- OCR 补充
- bbox 精修
- 图表对象化

---

## 难点 2：上下文拼接质量

用户真正需要的不是“能答”，而是：

- 选中这段时回答别跑题
- 提问公式时别只给泛泛解释
- 问“代码里哪里实现了它”时真能对上

### 解决思路

不要单一 RAG，做**分层上下文**：

- 局部对象
- 邻近上下文
- 章节摘要
- 全文摘要
- 代码摘要
- 用户画布当前节点

---

## 难点 3：画布交互设计

多数人会把“画布”做成一个花哨白板，结果没有科研效率。

### 解决思路

画布必须围绕这几个高频动作设计：

- 从 PDF 拉一段出来
- 让 AI 解释
- 把解释贴回去
- 在多个卡片间建立逻辑关系
- 最后导出为阅读笔记

也就是：**不是画图白板，而是研究推理工作台。**

---

## 难点 4：论文与代码对齐

这是最容易吹、最难做扎实的地方。

### 解决思路

分三级演进：

#### Level 1：弱对齐

靠 embedding + 文件摘要 + README

#### Level 2：结构对齐

加入函数/类/模块摘要与 symbol 索引

#### Level 3：语义对齐

method section ↔ implementation graph
loss / training / eval / config 自动匹配

你一开始做到 Level 1.5 就能用。

---

## 难点 5：成本控制

官网把 credits 设计得这么明显，说明它很在意：

- 解析成本
- 模型调用成本
- 存储成本
- GitHub 仓库处理成本

### 你的实现建议

模型分层：

- 轻任务：小模型
- 总结与解释：中模型
- 深度对齐与复杂比较：大模型

并且：

- 解析结果缓存
- chunk embedding 缓存
- section summary 缓存
- repo summary 缓存

不然成本会炸。

# 四、如果你要自主实现，正确路线不是“全做”，而是 4 阶段递进

---

## 阶段 1：做出最小可用版本 MVP

目标：证明“论文阅读 + AI 解释 + Zotero 接入”成立。

### 你要做的功能

1. 导入 Zotero 文献与 PDF
2. PDF 阅读
3. 框选文本提问
4. 基于选中文本 + 邻近上下文做问答
5. 自动生成 section summary
6. 基础笔记区

### 技术目标

- 不做代码库问答
- 不做复杂画布
- 不做订阅
- 不做多模型路由

### 验收标准

用户能完成：

- 打开论文
- 选中段落
- 问“这是什么意思”
- 保存答案作为笔记

这就够了。

---

## 阶段 2：做出 Vibero 的核心差异化 —— 交互画布

目标：从“AI PDF 阅读器”升级为“非线性阅读工具”。

### 新增功能

1. 卡片式节点系统
2. PDF 内容拖到画布
3. AI 回答拖到画布
4. 节点之间连线
5. 节点回跳源 PDF
6. 论文关键点自动卡片生成

### 验收标准

用户能围绕一篇论文在画布上形成：

- 问题
- 方法
- 图表解释
- 自己的研究注释

到这一步，产品形态就已经很接近官网描述了。

---

## 阶段 3：做论文 + 代码协同阅读

目标：补上官网第二个强卖点。

### 新增功能

1. GitHub repo 导入
2. README/目录/主要文件摘要
3. repo chunk 检索
4. 回答“论文中的方法在代码哪实现”

# 七、最推荐的实际开发顺序

这是最重要的一段。按这个顺序，你最不容易走弯路。

## 第一步：先做“可解释的 PDF 问答”

不要先做画布。
先做：

- 打开 PDF
- 选中段落
- AI 解释
- 显示来源页码

因为这是整个产品的最小真值闭环。

---

## 第二步：接 Zotero

当 PDF 问答能跑通后，再接：

- 文献列表
- 附件同步
- metadata

否则你会花大量时间在生态接入上，却没有核心体验。

---

## 第三步：加入“卡片化笔记”

这一步先别做复杂白板，只做：

- 将回答保存为卡片
- 将段落保存为卡片
- 支持简单关联

这是从“工具”走向“工作流”的关键。

---

## 第四步：升级为画布

当卡片系统稳定后，再加：

- 自由布局
- 连线
- 分组
- 回链 PDF

---

## 第五步：加入 GitHub 代码库问答

这个是增强项，不要前置。
因为没有论文阅读闭环前，代码库功能并不产生核心价值。

---

## 第六步：加入订阅与 credits

最后做商业层。
你前期先记录 usage log 即可。

---

# 八、如果你要“像 Vibero”，哪些地方必须像，哪些地方可以先不像

## 必须像的

1. **Zotero 兼容**
2. **选中即问**
3. **答案可沉淀为笔记**
4. **论文对象可回链原文**
5. **有“核心点定位”能力**

## 可以先不像的

1. 精致动画和品牌视觉
2. 完整计费体系
3. 多语言支持
4. 高级画布特效
5. 很深的论文-代码自动对齐

# 九、你可以把 Vibero 理解成什么产品范式

从产品范式上说，它更接近：

- Zotero × NotebookLM
- PDF 阅读器 × 白板笔记
- PaperQA × 可视化研究工作台
- GitHub code QA × scholarly workflow

所以如果你自主实现，你不要问：
“怎么复刻这个页面上的功能？”

你应该问：
**“怎么搭建一个以科研阅读为核心的 AI 工作台，其最小闭环是什么？”**

答案是：

> `导入论文 → 结构解析 → 局部提问 → 全局总结 → 沉淀卡片 → 组织画布 →（进阶）链接代码`
