下面直接给你一版可落地的方案。目标不是“泛泛而谈的插件构想”，而是**面向 Zotero 7 插件开发的 Vibero 核心功能实现蓝图**。

我先给结论：
**第一版不要试图在 Zotero 里完整复刻 Vibero 官网那种“重画布产品形态”，而要先做成“Reader 内 AI 增强 + 条目侧栏结构化洞察 + 轻量工作区”三件套。**
这是因为 Zotero 7 已经给插件提供了足够强的扩展点，包括 PDF reader 相关注入、自定义 item pane section，以及插件开发模板与工具链；这些能力足够支撑你先实现“选中即问、核心点定位、论文+代码辅助阅读、问答沉淀为笔记”等核心价值。([Zotero][1])

---

# 一、产品目标重述：插件版 Vibero 到底做什么

你要做的不是一个“聊天插件”，而是一个：

**Zotero 7 内嵌 AI 论文阅读增强层**

第一阶段只聚焦 5 个核心能力：

1. **PDF 选中即问**
2. **论文核心点定位**
3. **问答结果沉淀为笔记**
4. **论文 + GitHub 代码库协同问答**
5. **轻量非线性工作区**

这 5 个能力里，前 4 个都能很好地挂在 Zotero 7 现有插件扩展点上；第 5 个“轻量工作区”建议先做成插件内独立 tab / panel，而不是一开始就做超重白板。Zotero 7 官方已经提供了面向插件的 reader / item pane 能力扩展接口，而现有插件模板与社区项目也证明这条工程路径是成熟的。([Zotero][1])

# 三、模块拆解

## A. Reader Interaction Module

这是最核心的前台入口。
你要把 Zotero PDF reader 变成“可发起 AI 操作的上下文界面”。

### 目标功能

- 选中文本后弹出 AI 操作菜单
- 右键菜单增加：
  - 解释这段
  - 总结这页
  - 提取方法步骤
  - 识别局限性
  - 与代码对齐
  - 保存到 AI 工作区

- Reader toolbar 增加入口：
  - AI 摘要
  - 当前论文洞察
  - 打开工作区

### 对应 Zotero 7 能力

Zotero 7 文档明确支持：

- reader toolbar button
- reader tab panel
- reader context menu
- reader annotation context menu
- text selection popup
  这些就是你做“选中即问”和“Reader 内 AI 入口”的主战场。([Zotero][1])

### 输入

- 当前 reader item
- 当前选中文本
- 当前页码
- 当前 annotation（如果有）
- 邻近文本块

### 输出

- 发起 AI 任务
- 保存 context package
- 把结果推送到聊天面板或工作区

---

## B. AI Insight Pane Module

这是“核心点定位”模块，挂在 item pane 右侧最合适。

### 目标功能

在文献条目侧栏显示：

- 3 句论文摘要
- 研究问题
- 关键贡献
- 方法流程
- 重要图表
- 可能局限性
- 代码仓库绑定状态
- 最近 AI 对话摘要

### 对应 Zotero 7 能力

Zotero 7 官方提供了**自定义 item pane section / rows** 的 API，明确建议插件使用官方 API，而不是自己硬注入旧的信息面板。([Zotero][1])

### 为什么这块重要

因为这部分最像 Vibero 官网说的“核心点定位”。
而且它是“低侵入、高价值”的入口：用户即使不打开 PDF，也能先看 AI 提炼结果。

### 输入

- 当前 item metadata
- PDF 解析结果
- 已缓存的 section summary
- 用户绑定的 repo 信息

### 输出

- 结构化 insight cards
- 快捷动作按钮：
  - 打开详细问答
  - 写入笔记
  - 导出为 note
  - 发送到工作区

---

## C. Chat & Context Orchestrator

这是真正的“大脑”，不要直接把选中文本扔给模型。

### 子模块

1. **Intent Classifier**
   - explain
   - summarize
   - compare
   - critique
   - reproduce
   - code-align
   - extract

2. **Context Assembler**
   - 当前选区
   - 上下文段落
   - 当前页
   - 章节摘要
   - 论文全局摘要
   - 代码仓库摘要
   - 历史对话

3. **Prompt Router**
   - 文本解释 prompt
   - 方法拆解 prompt
   - 图表解释 prompt
   - 论文代码对齐 prompt
   - 局限性 prompt

4. **Response Normalizer**
   - 聊天文本
   - 可保存笔记块
   - 可插入工作区卡片
   - 可转 annotation comment

### 设计原则

**不要做“单一聊天框”，而要做“动作驱动的 AI”**。
用户点“解释这段”和点“与代码对齐”，背后的 context 组装完全不同。

---

## D. Notes / Annotation Sink

这决定你的插件能不能真正融入 Zotero 工作流。

### 目标功能

把 AI 结果写回 Zotero 生态：

- 写入 child note
- 写入 standalone note
- 写入 annotation comment / note
- 生成按模板组织的阅读笔记

### 推荐三种沉淀方式

1. **Quick Save**
   - 把一条 AI 回答保存为 item child note

2. **Append to Reading Note**
   - 把结果按模板插入某篇论文的“AI 阅读笔记”

3. **Attach to Annotation**
   - 把解释结果附着到当前高亮/选区

### 价值

这一步做对了，插件就不是“看完即失”的聊天工具，而是 Zotero 知识管理的一部分。

---

## E. Paper-Code Bridge Module

这是“论文 + 代码协同阅读”模块。

### 目标功能

- 在条目上绑定 GitHub repo URL
- 拉取 README / 目录 / 关键文件摘要
- 回答：
  - 论文方法在代码哪里实现
  - 某个公式可能对应哪个函数
  - 训练流程入口在哪
  - 评估脚本在哪

### 第一版不要做太重

不要一开始上 AST 全量分析。
先做三层：

#### 第 1 层：Repo metadata

- repo URL
- branch
- README
- stars/forks 可不做

#### 第 2 层：文件级摘要

- README 摘要
- 顶层目录摘要
- 关键 py/js/ipynb 文件摘要

#### 第 3 层：弱对齐问答

- 用论文 method summary 检索 repo chunks
- 返回最相关文件 / 函数片段
- 让 LLM 解释“为什么对应”

### 绑定方式

建议在 item pane section 增加：

- `Bind GitHub Repo`
- `Refresh Repo Index`
- `Ask with Code Context`

---

## F. Light Canvas / Workspace Module

这个模块是“轻量非线性阅读区”，不要一开始做成 full whiteboard。

### 第一版形态建议

做成一个**插件独立 tab / 对话式工作区**，里面支持：

- 卡片列表
- 分组
- 拖拽排序
- 引用回源 PDF 位置
- 从 AI 面板发送结果到工作区
- 从 Reader 选区发送片段到工作区

### 卡片类型

- Paper snippet card
- AI answer card
- Method card
- Limitation card
- Code snippet card
- User note card

### 为什么先这样

Zotero 里做“真正无限画布”不是不能做，但第一版很容易在 UI 容器适配上浪费时间。
先把“内容对象化”和“可回源”做对，再考虑几何画布。

---

## G. Local Cache & Job Manager

这是插件工程上非常关键但最容易被忽略的部分。

### 需要缓存什么

- 论文全局摘要
- section 摘要
- 当前 item 的 embeddings / chunk index
- repo index
- 历史对话
- AI 结果哈希缓存

### 为什么要做

否则每次打开条目都重新算：

- 成本高
- 体验慢
- API 花费不可控

### 建议缓存层

- 插件本地 SQLite / Indexed cache
- 附加 JSON cache
- itemID 维度索引

### Job Manager 需要管理

- parse paper job
- summarize paper job
- refresh repo job
- chat request job
- retry / cancel / progress

---

## H. Settings / API Key / Usage Module

Vibero 官网提到 AI 对话支持自定义 API Key，而核心解析统一提供服务。
你的插件第一版可以更简单：**全部支持用户自定义模型配置**。官网 FAQ 也说明了他们区分“自定义对话模型”与“平台统一解析服务”的模式。([Zotero][1])

### 建议设置项

- Provider: OpenAI / Anthropic / OpenRouter / 本地兼容接口
- API Key
- Base URL
- Embedding model
- Chat model
- Repo indexing model
- Max context
- Auto summarize on open
- Save AI outputs as note by default

### 统计项

- 当前会话 token 粗略估算
- 累计调用次数
- 每篇论文缓存状态
- 最近失败任务

# 五、用户交互流设计

## 流 1：选中即问

1. 用户在 PDF 中选中一段文字
2. 弹出菜单：
   - 解释
   - 简化
   - 提取方法
   - 找局限性
   - 与代码对齐

3. 插件抓取：
   - 选中文本
   - 所在页
   - 相邻上下文
   - 当前 item insight pack

4. 发给 orchestrator
5. 回答显示在 reader side panel
6. 用户可：
   - 保存为 note
   - 附着到 annotation
   - 发送到 workspace

## 流 2：打开论文即看核心点

1. 用户点击某条目
2. item pane 显示 AI Insight
3. 若无缓存则触发后台生成
4. 用户直接看到：
   - 3 句摘要
   - 贡献
   - 方法流程
   - 局限性

5. 一键打开详细问答

## 流 3：论文+代码协同问答

1. 用户在条目侧栏绑定 repo URL
2. 插件触发 repo ingest
3. 生成 README / 文件级摘要
4. 用户在 PDF 中选中方法描述
5. 点击“与代码对齐”
6. 系统返回最相关文件、函数及解释
7. 可保存到 workspace

## 流 4：沉淀为阅读笔记

1. 用户在聊天回复上点“保存”
2. 选择：
   - 追加到当前论文 AI note
   - 新建 child note
   - 存到 workspace

3. 形成 Zotero 内部长期知识资产

# 六、开发优先级清单

这里按真正可执行的顺序给你排。

## P0：工程脚手架与基础运行

- 建立基础模块目录
- 建立本地存储层
- 做设置页与 API Key 存储

### 推荐起点

- Zotero 官方 sample plugin `make-it-red`
- windingwind 的 `zotero-plugin-template`
- `zotero-plugin-toolkit`
  这些都能大幅降低 Zotero 7 插件开发的上手成本。([GitHub][2])

### P0 验收

- 插件可安装
- 有设置页
- 能读到当前选中 item
- 能弹出一个基础对话框 / 面板

---

## P1：Reader 内“选中即问”

这是第一优先级里的第一位。

### 要做的事

- 接入 reader text selection popup
- 增加右键菜单操作
- 获取当前 item / page / selection
- 调用一个简单 LLM 接口
- 返回结果到 side panel

### 为什么它最先做

因为这是最直接验证需求的功能。
如果这个功能用户不用，其它大部分复杂设计都不重要。

### P1 验收

- 在 PDF 中选中文字
- 点击“解释这段”
- 2~5 秒内返回结果
- 可复制回答

---

## P2：AI Insight Pane

第二优先级。

### 要做的事

- 在 item pane 注册自定义 section
- 打通“生成本论文洞察包”流程
- 展示：
  - short summary
  - contributions
  - method steps
  - limitations

### P2 验收

- 选中文献条目时右侧能看到 AI 洞察
- 有缓存，重复打开不重新生成
- 支持刷新

---

## P3：Save to Note / Annotation

第三优先级。

### 要做的事

- 把 AI 回答存成 child note
- 支持追加到统一阅读笔记
- 支持保存与当前 annotation 的关联

### 为什么这一步重要

这一步做完，你的插件才真正接到 Zotero 的“知识管理主链路”。

### P3 验收

- 任意 AI 回复可一键保存到该论文笔记
- 笔记中包含来源页码与时间戳

---

## P4：论文解析缓存与结构摘要

第四优先级。

### 要做的事

- 做 chunking
- 做 section 级缓存
- 做全文 summary cache
- 建立 paper parse state

### 为什么不放更前

因为可以先用“现取文本 + 简单上下文”做 MVP。
解析层太早做重，会拖慢验证。

### P4 验收

- 同一篇论文二次使用明显更快
- method / limitation 等结构化输出更稳定

---

## P5：GitHub Repo Binding

第五优先级。

### 要做的事

- 条目绑定 repo URL
- 拉 README
- 索引关键文件
- 形成 repo summary

### P5 验收

- 某篇论文可以绑定一个 repo
- 能返回 repo 摘要
- 能列出 3~5 个最关键文件

---

## P6：Paper-Code Align Chat

第六优先级。

### 要做的事

- 将论文 method summary 与 repo chunks 做相似检索
- 在问答中插入 repo context
- 输出：
  - 对应文件
  - 对应函数 / 模块
  - 对应理由

### P6 验收

- 用户问“论文方法在代码哪里实现”
- 插件返回文件路径和解释，不是泛泛而谈

---

## P7：Light Workspace

第七优先级。

### 要做的事

- 独立 workspace tab/panel
- 卡片化保存内容
- 支持拖拽排序与分组
- 支持回跳源 PDF / repo file

### 为什么放后面

因为工作区的价值依赖前面的内容对象化是否成熟。

### P7 验收

- 至少能积累 snippet / ai / note / code 四类卡片
- 卡片能回源
- 支持简单分组

## P8：体验打磨与商业化预留

最后一层。

### 要做的事

- 失败重试
- 并发与节流

# 八、第一版技术实现策略

## 1. 不要一开始做 OCR

先只支持：

- Zotero 内可打开的文本型 PDF
- 通过 reader / PDF 文本层拿到的文本
- 简单 chunking

## 2. 不要一开始做向量库大工程

先本地缓存：

- 章节摘要
- 全文摘要
- 关键段落索引
  必要时再加 embedding。

## 3. 不要一开始做复杂画布

先做“卡片工作区”。

## 4. 不要一开始做多模型路由

先只支持：

- 一个 chat model
- 一个 summary model
- 一个 embedding model

## 5. 所有 AI 输出都要有 source anchor

至少带：

- 页码
- 选区文本摘要
- 关联 itemID
  否则后期很难做可信引用和回跳。

# 十、最终建议

你现在最正确的落地方式不是“先想完整产品”，而是先把下面这个最小闭环做通：

**在 Zotero 7 中打开 PDF → 选中一句话 → AI 解释 → 一键保存到该论文笔记**

只要这个闭环稳定、快、好用，你后面的：

- 核心点定位
- 论文+代码协同阅读
