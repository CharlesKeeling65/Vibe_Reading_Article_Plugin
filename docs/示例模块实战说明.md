# 示例模块实战说明

这份文档聚焦 [src/modules/examples.ts](src/modules/examples.ts) 里的示例代码，说明每一组示例在模板里做了什么，以及迁移到真实插件开发时通常应该如何使用。

## 总体定位

[src/modules/examples.ts](src/modules/examples.ts) 不是业务实现层，而是一组 API 能力样例库。

它的作用有三点：

1. 展示 Zotero 与 zotero-plugin-toolkit 常见扩展点的最小用法。
2. 给 [src/hooks.ts](src/hooks.ts) 提供可注册、可触发的演示能力。
3. 作为后续业务开发时的“剪切板代码来源”，你可以删掉不需要的示例，只保留真正需要的扩展入口。

如果你准备把这个模板改造成正式插件，推荐做法不是继续往示例工厂里堆业务，而是：

1. 保留 hooks 里的注册入口。
2. 把具体功能拆到单独模块。
3. 只让 hooks 和 examples 风格的注册层负责“接入 Zotero”，不要负责完整业务流程。

## 装饰器 example

文件开头的 `example` 装饰器只是一个日志包装器。它会在每个示例方法执行前后把调用记录输出到 `ztoolkit.log`。

它的实际用途是：

1. 让你在调试时快速知道哪个 demo 被触发了。
2. 包住异常，便于在 Zotero 调试输出中定位出错示例。

真实开发里通常有两种处理方式：

1. 保留它，继续作为开发期日志辅助。
2. 删除它，改用你自己的日志封装。

## BasicExampleFactory

### registerNotifier

这个方法注册了 Zotero 的观察者，监听 `tab`、`item`、`file` 三类变化。收到通知后，不直接处理业务，而是转发给 [src/hooks.ts](src/hooks.ts) 里的 `onNotify`。

这说明模板的设计思路是：

1. 注册层负责接入 Zotero 事件系统。
2. hooks 层负责分发。
3. 真正的业务回调应该继续下沉到独立函数。

真实开发适用场景：

1. 监听选中条目变化后刷新侧边栏。
2. 监听附件导入后触发元数据解析。
3. 监听 reader 标签页切换后同步阅读状态。

需要注意的是，通知回调常常很多、很频繁，不适合在这里直接做重活。更稳妥的做法是：

1. 在这里先过滤事件类型。
2. 只把需要的上下文传给业务层。
3. 必要时做防抖或批处理。

### exampleNotifierCallback

这里只是弹一个进度窗，证明通知确实触发了。

真实插件里，这一类回调更适合替换成：

1. 刷新某个面板内容。
2. 更新缓存。
3. 写入日志或遥测。

### registerPrefs

这个方法把 [addon/content/preferences.xhtml](addon/content/preferences.xhtml) 注册进 Zotero 的首选项界面。

这相当于告诉 Zotero：

1. 我的插件有一个设置页。
2. 页面结构在 XHTML 文件里。
3. 页面标题和图标是什么。

真实开发里，这通常是所有“用户可配置插件”的必备入口。

## KeyExampleFactory

### registerShortcuts

这个方法通过 `ztoolkit.Keyboard.register` 注册快捷键监听。模板里示例用了 `Shift+L` 和 `Shift+S`，再分发到 `addon.hooks.onShortcuts`。

它表达的核心思路是：

1. 快捷键监听统一注册。
2. 快捷键只负责触发动作标识。
3. 实际业务动作放到 hooks 或业务层。

真实开发适用场景：

1. 给当前条目快速生成笔记。
2. 在阅读器里触发高亮、摘录、翻译。
3. 打开插件自己的命令面板或侧栏。

### exampleShortcutLargerCallback / exampleShortcutSmallerCallback

这两个方法只是演示快捷键被正确触发。真实项目里你通常会把它们替换为：

1. 改变阅读字号。
2. 调整面板宽度。
3. 执行某个与当前上下文相关的命令。

## UIExampleFactory

这是模板里最重要的一组示例，因为 Zotero 插件大多数“可见功能”都落在 UI 扩展里。

### registerStyleSheet

它把 [addon/content/zoteroPane.css](addon/content/zoteroPane.css) 注入到主窗口文档，并给目标节点加上 CSS 类。

真实开发作用：

1. 改造 Zotero 主界面样式。
2. 为你自己的面板、按钮、行、列提供样式。
3. 对现有界面做轻量视觉增强。

如果你的插件要做复杂 UI，这个入口几乎一定会保留。

### registerRightClickMenuItem

这个方法在条目右键菜单中插入一个菜单项，点击后触发对话框示例。

真实开发适用场景：

1. 对选中文献执行 AI 总结。
2. 批量修改条目字段。
3. 导出选中条目到外部系统。

这是非常典型的“以当前选中条目为上下文”的入口。

### registerRightClickMenuPopup

这个方法演示如何在已有右键菜单项旁边再挂一个子菜单。

适合的真实场景：

1. 一个主功能下面拆出多个动作。
2. 不同导出格式分别作为子菜单项。
3. 针对当前条目提供多个自动化处理选项。

### registerWindowMenuWithSeparator

这个方法往顶部 File 菜单里插入分隔线和新菜单项。

它更适合全局命令，而不是依赖当前选中条目的局部操作。

真实开发适用场景：

1. 打开插件总设置窗口。
2. 执行全库扫描。
3. 打开日志、调试面板、同步入口。

### registerExtraColumn

这个方法给条目列表注册一个新列，列值由 `dataProvider` 根据条目生成。

真实开发适用场景：

1. 显示 AI 评分。
2. 显示阅读进度。
3. 显示自定义标签或同步状态。

这种方式适合“每个条目都有一个可快速浏览的计算结果”。

### registerExtraColumnWithCustomCell

这个方法和上一个的区别在于，它不仅提供值，还接管了单元格渲染。

这意味着你可以自定义：

1. 颜色。
2. 图标。
3. 文本结构。
4. 更复杂的 DOM 表现。

真实开发里它适合：

1. 用颜色标出优先级。
2. 在单元格里显示状态徽标。
3. 用图标加文字表示处理结果。

### registerItemPaneCustomInfoRow

这个方法在条目详情区注册一行可编辑的信息行，并把它映射到条目的 title 字段。

这类能力很适合做：

1. 自定义元数据映射展示。
2. 给现有字段提供更直观的编辑入口。
3. 绑定插件自己的扩展字段或计算字段。

如果你的插件主要围绕条目元数据工作，这是非常值得保留的扩展点。

### registerItemPaneSection

这个方法在条目侧边栏注册一个完整 section，并在 `onRender` 里渲染内容。

它适合承载比“单行字段”更复杂的内容，比如：

1. 文献摘要。
2. AI 分析结果。
3. 关联笔记列表。
4. 远程服务返回的附加信息。

### registerReaderItemPaneSection

这是模板里最值得认真研究的一个示例，因为它几乎把 Reader 侧边栏 section 的完整生命周期都示范了一遍。

它包含：

1. `onInit`：section 第一次创建时触发。
2. `onItemChange`：当前阅读条目变化时触发。
3. `onRender`：同步渲染，用于先给出占位内容。
4. `onAsyncRender`：异步渲染，用于加载真正数据。
5. `onToggle`：面板折叠/展开时触发。
6. `onDestroy`：面板被销毁时触发。
7. `sectionButtons`：给 section 头部添加按钮。

真实开发里，这个模式非常适合：

1. 阅读器里显示 AI 伴读结果。
2. 显示当前 PDF 页面的上下文分析。
3. 在侧栏里展示摘录、标签、问题列表。
4. 接入网络请求，先同步占位，再异步回填数据。

如果你的目标是“阅读辅助”插件，那么这一块几乎就是你后续业务界面的主战场。

## PromptExampleFactory

这组示例展示如何做一个命令面板式入口。

### registerNormalCommandExample

注册一个普通命令，打开 Prompt 后始终可见。

真实开发适用场景：

1. 打开全局搜索。
2. 触发某个无上下文限制的命令。
3. 提供开发者调试入口。

### registerAnonymousCommandExample

这个示例更像“带搜索结果面板的命令”。它把输入框内容转成 Zotero.Search，再把结果渲染成候选列表，点击后跳转到对应条目。

它的价值不在于代码本身是否可直接复用，而在于展示了一种模式：

1. 读取 Prompt 输入。
2. 做搜索或计算。
3. 动态创建结果列表。
4. 让结果项可以直接驱动 Zotero 界面跳转。

真实开发里可以把它改造成：

1. 文献模糊检索入口。
2. 笔记块跳转器。
3. 根据关键词查找摘要、标签或高亮。

需要注意：这个示例更偏演示，真实项目里最好进一步整理搜索逻辑、异步过滤逻辑和渲染复用。

### registerConditionalCommandExample

这个示例展示了 `when` 条件。只有当前存在选中条目时，命令才会显示。

这非常适合上下文敏感命令，例如：

1. 只有选中文献时才允许“生成摘要”。
2. 只有选中附件时才允许“发送到阅读器分析”。
3. 只有在 reader 页面时才显示“提取当前页高亮”。

## HelperExampleFactory

这组示例主要是辅助能力，不是 Zotero 专属扩展点，但在实际开发里很常用。

### dialogExample

这个示例展示 toolkit 的 Dialog 构建器如何：

1. 通过网格布局添加控件。
2. 用 `data-bind` 把控件和状态对象双向绑定。
3. 监听按钮点击和窗口关闭。
4. 在对话框关闭后读取用户输入结果。

真实开发适用场景：

1. 批量处理前让用户确认参数。
2. 收集 API Key 或处理选项。
3. 做一个轻量工具窗口。

### clipboardExample

演示如何同时复制纯文本和 HTML 到剪贴板。

这适合：

1. 复制富文本引用。
2. 复制 Markdown 链接。
3. 复制带格式摘要结果。

### filePickerExample

演示文件选择器的打开方式。

真实开发适用场景：

1. 导入配置文件。
2. 选择本地模型或词典资源。
3. 导出结果到指定位置。

### progressWindowExample

演示进度窗的最基础用法。

对于 Zotero 插件来说，这通常是非常实用的反馈方式，适合：

1. 批量处理条目。
2. 下载或同步数据。
3. 告知用户当前阶段和完成状态。

### vtableExample

这个方法本身只弹窗提示，但它把你引回 [src/modules/preferenceScript.ts](src/modules/preferenceScript.ts)，因为真正的虚拟表格示例写在那里。

说明模板作者的意图是：

1. 表格类 UI 更适合放在偏好页或专门窗口里。
2. 它通常不是一个孤立按钮，而是一整套状态管理和渲染逻辑。

## 推荐的删改策略

如果你准备把模板改造成自己的插件，建议这样处理 [src/modules/examples.ts](src/modules/examples.ts)：

1. 保留 `registerNotifier`、`registerPrefs`、`registerReaderItemPaneSection` 这些与你目标功能高度相关的入口。
2. 删除纯演示性质、与你业务无关的菜单、弹窗和提示示例。
3. 把每个保留的示例迁移成独立业务模块，例如 `readerPanel.ts`、`commands.ts`、`itemColumns.ts`。
4. 让 [src/hooks.ts](src/hooks.ts) 只负责注册和路由，不直接承担业务实现。

## 如果你的目标是“阅读辅助插件”

结合当前仓库名称和规划文档，你最值得优先复用的是这几块：

1. `registerNotifier`：感知阅读器切换、条目变化。
2. `registerReaderItemPaneSection`：承载阅读分析、问题提示、摘要结果。
3. `registerConditionalCommandExample`：提供上下文敏感命令入口。
4. `dialogExample`：做设置或确认弹窗。
5. [src/modules/preferenceScript.ts](src/modules/preferenceScript.ts) 里的偏好页表格模式：做配置管理。

而这些示例更像模板遗留 demo，可按需删除：

1. `registerStyleSheet` 里的 make-it-red 风格演示。
2. 简单的弹窗式快捷键回调。
3. 只用于展示 toolkit API 的临时提示窗示例。
